# SPS2 Setup Assistant 1.2.0

VRCFuryでSPS3が公開され、従来のSPS2 Setup Assistant 1.1.1ではアバターのビルドが止まる問題が確認されています。SPS3への正式対応バージョンとなるv2.0.0は開発中のため、まずはこのビルド停止への対処を先行して届ける暫定正式バージョンとして、1.2.0を公開します。

1.2.0-beta.5をベースに、VRChat SDK 3.10.6に対応するため、NDMF Installerが導入するSPS for NDMFを1.1436.0に更新しました。SPS3への正式対応は、今後のv2.0.0で行う予定です。

## 既知の制限

- **「後方互換性」をOFFにしても反映されないことがあります。**
  VRCFuryでは、OFFにしても古い方式向けのメニューや互換用の仕組みがアバターに残る問題があります。このバージョンでは修正していません。
- **VRCFuryからSPS for NDMFへの切り替えが止まることがあります。**
  すでにセットアップしたアバターで使用する方式を切り替えると、設定の確認中に停止する場合があります。Installerを入れ替えるだけでは、既存のセットアップは自動変換されません。
- **NDMFで同じ名前の部位を複数使っている場合、名前と保存済み状態に注意してください。**
  重複を区別する番号の付け方が変わり、メニューや外部連携で使う名前が変わります。外部ツールと連携している場合は、その設定を見直してください。VRChatで保存していた各部位のON/OFF状態が引き継がれない可能性もあります。

更新前にプロジェクト全体をバックアップしてください。更新後は設定とメニューを確認し、アバターを再ビルド・再アップロードして、各部位の動作を確認してください。

## 過去の変更履歴・使い方

以下は beta.5 以前の記録です。beta の選択案内や当時の検証状況を現在の導入手順・検証結果として扱わないでください。

## 1.2.0-beta.4：各SPS基盤の標準ビルドに対応

SPS for NDMFは標準のビルド処理を使用します。VRCFuryでは、Fix Write DefaultsがDisabledの場合に必要なSocket・Legacy・Stealthの復元処理だけを残しました。

メニュー構成・初期値・保存設定は、選択したSPS基盤の標準仕様を使用します。メニュー言語はソケット名のみに適用され、Local Onlyは基盤側のStealth Modeを使用します。従来のSPS2メニューの並びや状態の保存とは変わるため、更新後に確認してください。

既存のセットアップで表示名を反映する場合は、「置き換えずに変更を反映」を実行して保存してください。表示名の反映だけなら、再生成は不要です。ビルドの変更を反映するにはアバターの再ビルド・再アップロードが必要です。

beta版です。導入前にプロジェクトをバックアップし、VCC/ALCOMではプレリリースを表示して1.2.0-beta.4を選択してください。

## 1.2.0-beta.3：指わっかの仮配置と警告

自動計算した指ポーズの指先間隔が目安を超えても、残る形状・校正チェックを通れば仮配置し、部位名付きの警告を表示します。実際に使うポーズで位置と向きを確認してください。不正な形状や骨参照では引き続き生成を停止し、保存済み校正・手動調整は自動で置き換えません。

実際の利用条件では生成後に確認してください。過去の試験結果と既知の未解決事項は[検証記録](Docs/KNOWN_ISSUES.md)に残しています。

## 1.2.0-beta.2：生成済み設定の基盤切替

生成済みセットアップの VRCFury／SPS for NDMF を、配置・校正・共通設定を保持して切り替えられます。
移行前に両方の依存を導入してください。元の基盤や所有情報が欠けている場合は変更せず、手動削除して新規生成するか元の依存を再導入する案内を表示します。
他の設定変更は切替とは別に適用してください。Prefab source を持つ生成物、PrefabMode、未知の native 編集・外部 Component 参照は切替を停止します。非一様 Socket／祖先 scale は native 基盤で非対応です。
専用 fixture の Unity 内移行・保存再読込・両 SDK build は確認済みですが、VRC PC と実パッケージ欠落からの復旧は未確認です。導入前にバックアップしてください。

# SPS2 Setup Assistant

VRChatアバターへのSPS2セットアップを補助するUnity Editorツール

使用する部位を選ぶだけでソケットの配置やメニューの生成をまとめて行えます。

## 導入

### [▶ VCC / ALCOMに追加](https://lumakroma.github.io/SPS2-Setup-Assistant/)

上のリンクから追加ページを開き、VCCまたはALCOMでリポジトリの追加を承認してください。

続いて導入先のアバタープロジェクトを開き、パッケージ一覧から **SPS2 Setup Assistant** を追加してください。

手動で追加する場合のリポジトリURL：`https://lumakroma.github.io/SPS2-Setup-Assistant/index.json`

## 使い方

## 1.1.1：指わっかのscale対応

指わっかは、アバターroot・祖先・指関節の正の一様scaleに対応します。
非一様・負のscaleでも黄色の注意を表示して生成を続行します。この場合、指わっかの位置・向き・サイズは保証されません。生成後に確認し、手動で調整してください。
保存済み校正があれば再利用し、初回は現在の指関節を基準に仮配置します。
0scaleなどで安全に計算できない指わっかだけを省略し、他の生成可能な部位は続行します。保存済み校正は保持します。
生成可能な部位が残らない場合や、アバターroot自体が退化して安全に配置できない場合は、黄色の注意を表示し、既存の設定・生成物を変更しません。
scaleを変更した後は設定を反映、または再生成してください。実行中のscaleアニメーションへの自動追従は対象外です。
従来のscale=1設定と、保存した校正・手動調整を引き継ぎます。安定版1.1.1に含まれています。


### v1.1.0以降：言語とメニュー表示名

「画面の言語」と、アバターに保存する「メニューの言語」を別々に選択できます。
日本語・英語・韓国語・中国語（簡体字／繁体字）に対応します。
部位ごとの「メニュー表示名」は空欄で標準名を使用し、入力した名前は言語や
プリセットを変えても保持します。「標準名に戻す」で個別名を解除できます。
変更後は「置き換えずに変更を反映」または再生成で保存してください。
設定した表示名は生成・Apply時にSocket側の `Name in menu` へ保存します。
ビルドではSocketに保存された名前を使用します。基盤側の共通メニューは翻訳しません。

一番シンプルな方法は、上部メニュー欄から `Tools > LumaKroma > SPS2 Setup Assistant` を開いて対象アバターを指定 → `プレハブを生成`。

生成前にプリセットや使用する部位、深度アクション、設定項目をカスタマイズできます。

設定の変更・再生成、テストプラグの配置もできます。

対象はHumanoidアバターのみです。自動配置の結果はアバターによって異なるため、生成後に位置や向きを確認してください。

## 機能

- プリセットを使ったセットアップ
- 使用する部位に応じたソケットの自動配置
- ソケットを操作するメニューの自動生成
- 深度アクションの設定
- 口と肛門をつなぐ貫通経路の生成
- Auto Mode・後方互換性の設定
- 手動調整した位置を維持した設定の反映
- 設定に合わせた再生成
- 通常のテストプラグと、貫通確認用の長いテストプラグの配置

## 依存

- Unity 2022.3
- VRChat Avatars SDK
- VRCFury または SPS for NDMF（選択した系列を別途導入）
- lilToon（テストプラグの表示用）
- Modular Avatar（Furyでは任意、SPS for NDMFでは1.18.1以上・2未満が必要）
- NDMF（SPS for NDMFでは1.11以上・2未満が必要）

## 従来のAssets版からの移行

1.1.0ではVPMの旧版移行機能を使い、導入時に旧 `Assets/LumaKroma/SPS2SetupAssistant` フォルダーを削除対象にします。移動済みの旧フォルダーもGUIDで検出される場合があります。設定保存先 `Assets/SPS2Settings` は削除対象に含めません。

**移行前にUnityを終了し、プロジェクト全体をプロジェクト外へバックアップしてください。** 旧フォルダー内へ追加したファイルや編集した内容も削除対象です。必要な内容を確認・退避してから進めてください。この機能による自動バックアップや、ごみ箱からの復旧は保証されません。

VPMインストーラーでは、表示される削除対象を確認してからInstallを選んでください。対象が想定と異なる場合や内容を確認できない場合はCancelしてください。VCC/ALCOM経由でも同じ旧版削除情報が使われるため、先にバックアップと内容確認が必要です。

導入後はコンパイルと保存済み設定・シーン・プレハブの参照を確認してください。問題があればUnityを終了し、移行前のバックアップから復元してください。VPM版を導入済みの場合、インストーラーが「Nothing TO DO」で終了して旧版が残ることがあります。再インポートで必ず重複を解消できるわけではありません。
